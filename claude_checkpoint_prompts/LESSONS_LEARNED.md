# Lessons learned — append-only

Things this session learned the hard way. **Read before doing the same kind of operation.**

---

## 1. gcloud ssh + background processes hang the local channel

**Problem:** `gcloud compute ssh VM --command='nohup long_cmd &'` hangs the local terminal even with `nohup &`. The remote process starts, but the local gcloud client never returns. If you `Ctrl-C` or `TaskStop` the local task, the remote process keeps running — easy to end up with two SU2 processes fighting for memory.

**Fix:**
```bash
gcloud compute ssh VM --zone=ZONE --command='setsid bash -c "long_cmd > log 2>&1 & echo \$! > pid" < /dev/null > /dev/null 2>&1'
```

Three pieces matter:
- `setsid` — detaches into a new session so the process survives SSH channel close
- `< /dev/null` — closes stdin
- `> /dev/null 2>&1` (on the OUTER gcloud) — closes local stdout/stderr so gcloud's channel can exit cleanly

**Always verify after launch** by `gcloud compute ssh ... --command='ps -ef | grep YOUR_PROCESS'`. If you see two instances of the same process, kill the duplicate.

This is also saved in user memory at `reference_gcloud_ssh_background.md`.

## 2. `pkill -f` matches against cmdline, NOT cwd

**Problem:** SU2's cmdline is just `/opt/su2-nemo/bin/SU2_CFD run.cfg` — no stage info anywhere in the command line. The stage is encoded only in the **cwd** (`/home/yarden/ram_c_runs/ramC_refined_M18_0_A61/`).

`pkill -f "SU2_CFD.*ramC_refined_M18"` returns ZERO matches even when an M18 SU2 is actively running.

**Fix:** match by cwd via `/proc/$pid/cwd`:
```bash
for pid in $(pgrep -x SU2_CFD); do
    cwd=$(readlink /proc/$pid/cwd 2>/dev/null)
    if [[ "$cwd" == *ramC_refined_M18* ]]; then
        kill -9 "$pid"
    fi
done
```

## 3. SU2-NEMO is OpenMP-only on this VM (no MPI)

**`ldd /opt/su2-nemo/bin/SU2_CFD`** shows `libgomp` but no `libmpi`. Pre-processing (RCM reorder, element connectivity) is **single-threaded** regardless of how many cores the VM has.

For a 4.5M-tet mesh, preprocessing alone took 33+ minutes with no progress visible. Solution: coarsen the mesh until preprocessing completes in a reasonable time. We landed at **2.67M tets** as the practical sweet spot.

**Future improvement:** rebuild SU2-NEMO with MPI (`./meson.py build -Dwith-mpi=ON`) — would give 8–12× speedup per iter. ~4-6 hours of VM-admin work. Worth doing before any production batch.

## 4. Python on Windows defaults to cp1252, NOT utf-8

**Problem:** `print(f"ne = {ne:.2e} m⁻³")` crashes with `UnicodeEncodeError`. Same for `→`, `×`, `Δ`, `°`, etc.

**Fix:** prefix every Python invocation with `PYTHONIOENCODING=utf-8`:
```bash
PYTHONIOENCODING=utf-8 python scripts/validate_ram_c_nemo.py ...
```

Or in a script, add at the top of `__main__`:
```python
import sys
if sys.stdout.encoding.lower() not in ("utf-8", "utf8"):
    try:
        sys.stdout.reconfigure(encoding="utf-8")
        sys.stderr.reconfigure(encoding="utf-8")
    except Exception:
        pass
```

Also: `Path.write_text(...)` defaults to cp1252 too. Always pass `encoding="utf-8"` explicitly when writing markdown/JSON files.

## 5. Bash variable substitution in monitor scripts

**Problem:** A monitor script with `${RUNS}/ramC_refined_M${mach/./_}_A61` produces `M10_0_A61` for `mach=10.0`. But if you hardcode `${RUNS}/ramC_refined_M10_A61` (no `_0`) in another place, you get a `cp` failure that crashes `set -e` chains.

**Fix:** always use a single helper function for stage-dir naming, never hardcode literals:
```bash
stage_dir_for_mach() {
    local mach=$1
    echo "${RUNS}/ramC_${CASE}_M${mach/./_}_A${ALT}"
}
```

The `scripts/ram_c_unified_ramp.sh` does this. Always reference stage dirs through the helper.

## 6. matplotlib + Python-on-Windows + reportlab interactions

When generating PDFs from matplotlib figures inside reportlab:
- Use `matplotlib.use("Agg")` BEFORE `import matplotlib.pyplot` — non-interactive backend, required for headless PDF gen
- Save figures to `BytesIO` buffers, not temporary files (cleaner, faster, no FS race)
- Don't expect `matplotlib.colors.LogNorm` to work with `vmin=0` — clip ne floor to e.g. 1e15 before plotting

## 7. cdk synth output goes to cdk.out/

**Don't** commit `cdk.out/` — it's regenerated by every `cdk synth`. Already in `.gitignore` after `bd69e20`.

## 8. Don't create `lambda/` as a Python package

`lambda` is a Python keyword — `from lambda.simulation_complete import handler` is a syntax error. Use `sys.path.insert(0, str(LAMBDA_DIR))` then `import index` instead. The contract tests use this pattern.

---

## 9. Concurrent commits between two Claude instances on the same working tree

When `git status` shows files modified that you didn't edit, the other instance touched them. **Never `git add .` blindly.** Instead, stage only your files explicitly:

```bash
git add path/to/your/file1 path/to/your/file2
```

If you accidentally include their unstaged changes in your commit, you'll commit code you haven't reviewed and may break their in-progress work.

---

## 10. Long-running monitors expire silently

Background `Monitor` tasks with `persistent: true` run until session end or explicit `TaskStop`. If you start a monitor and the user's Claude Code session ends, the monitor dies too. **For multi-day waits, make sure the user knows the monitor is local to your session.**

---

## 11. `cdk synth` requires both Python deps AND npm CDK CLI

Backend CI installs:
```yaml
- run: pip install --no-cache-dir aws-cdk-lib constructs
- run: npm install -g aws-cdk
```

Forgetting either causes opaque CFN errors at synth time.

## 12. Excel files lock when open in Windows Excel

Generating an `.xlsx` while Excel has the file open fails with `PermissionError`. The `make_roadmap_xlsx.py` script auto-falls-back to `_v1.xlsx`, `_v2.xlsx`, etc. Tell the user to close Excel before regenerating, or accept the version-bumped file.

---

## 13. The phase2 watcher's `pkill` race window

When the original ramp script's M15 stage finishes, the watcher polls every 5 seconds for the `su2.exitcode` file. Between exit-code-write and watcher-detection, the original script may have ALREADY launched M18 SU2. The watcher then needs to kill that nascent M18 SU2 — see lesson #2 for the cwd-based pkill pattern.

---

## 14. Don't trust task descriptions over git log

The TaskCreate / TaskUpdate task list shows tasks like "Refine RAM-C mesh for sheath resolution" that may be outdated. Always cross-check against `git log --oneline -20` for the current state. Task list is for short-horizon planning; git log is the source of truth for what's actually shipped.

---

## 15. Smoke-test new scripts BEFORE adding to a long-running pipeline

`finalize_m22_5_result.py` was tested by running it on the EXISTING M22.5 small-mesh VTU before M22.5 (refined) finished. Same for `make_paper_figures.py`. Catching argparse / path-resolution bugs at script-write time saves a real "the result is in but the finalizer crashed at step 4" demo embarrassment.
